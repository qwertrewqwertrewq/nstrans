# 机器翻译基准

测试时间：2026-09-24；设备：MacBook Air（Apple M4、16GB RAM）；系统：macOS 27.2。网页源通过 NSTrans 自身的 Vite/Tauri 同构请求层运行，本机 NLLB 使用项目镜像中的 Q8 ONNX 模型。数字是单次端到端墙钟时间，不代表服务商 SLA。

测试文本覆盖三种情况：普通日文单句、四条游戏字幕同时提交、约 150 字的连续长句。完整可复现实验脚本为 [`tools/testing/benchmark-machine-translation.mjs`](../tools/testing/benchmark-machine-translation.mjs)。

| 服务 | 普通单句 | 四句并行/批处理 | 长句 | 本次结果 |
| --- | ---: | ---: | ---: | --- |
| 网易有道网页 | 229 ms | 262 ms | 147 ms | 全部成功 |
| Google 网页 | 343 ms | 521 ms | 536 ms | 单句成功；并发与后续长句被 HTTP 429 限流 |
| Bing 网页 | 296 ms | 286 ms | 204 ms | 当前出口 IP 三组均触发网页验证，未取得译文 |
| DeepL 网页 | 2,421 ms | 1,143 ms | 439 ms | 单句成功；并发触发 429，紧随其后的长句仍处于限流窗口 |
| 本机 NLLB-600M Q8 | 686 ms | 817 ms | 2,785 ms | 热运行全部成功；首次冷加载另需 2,126 ms |

NLLB 热运行示例：单句 `今日はハイラル平原を探索します。` 输出“今天我们要去探索海拉平原.”。长句能返回译文，但本次结果遗漏了末段内容，说明 NLLB-600M 更适合短句/字幕，长段落应优先使用 TranslateGemma 或远程模型。

网页源的限流结果也是测试结论，而不是脚本错误。正式运行时，网易有道最多三路、Google 最多两路并发；Bing 与 DeepL 串行，避免一帧 OCR 触发突发请求。所有网页源都会在验证、限流或页面结构改变时明确报错，客户端可切换服务。
