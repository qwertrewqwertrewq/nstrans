# NSTrans 0.1.2 Alpha

本版本加入本机与网页机器翻译、连续 OCR 结果复用，并继续提供 `WithLlama` 与 `RemoteOnly` 两类构建。Alpha 版本用于兼容性与效果验证；macOS 未公证、iPadOS 需要自行签名，Android 使用调试签名。

## 机器翻译

- `WithLlama` 可按需下载并离线运行 NLLB-200 Distilled 600M Q8 ONNX 模型；模型包约 874 MiB，不包含在安装包中。
- 所有构建均可选择网易有道、Google、Bing、DeepL 网页翻译，不需要 API Key。公开网页协议可能受到地区网络、验证码、频率限制或页面改版影响。
- OCR 输出经过标准化后会建立会话级译文族。新文本与任一已有成员的编辑差异不超过 10% 时，直接递归复用译文，不再次请求翻译器；切换输入源或重置时清空。

### 机器翻译实测

测试设备为 Apple M4、16GB RAM 的 MacBook Air，系统 macOS 27.2；数据是 2026-09-24 的单次端到端墙钟时间，不代表服务商 SLA。失败项的耗时表示服务返回验证或限流所需时间，并非成功翻译延迟。

| 服务 | 普通单句 | 四句并行/批处理 | 长句 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 网易有道网页 | 229 ms | 262 ms | 147 ms | 三组成功 |
| Google 网页 | 343 ms | 521 ms | 536 ms | 单句成功，并发及后续长句触发 HTTP 429 |
| Bing 网页 | 296 ms | 286 ms | 204 ms | 当前出口 IP 三组均触发网页验证 |
| DeepL 网页 | 2,421 ms | 1,143 ms | 439 ms | 单句成功，并发触发 HTTP 429 |
| 本机 NLLB-600M Q8 | 686 ms | 817 ms | 2,785 ms | 热运行三组成功；首次冷加载另需 2,126 ms |

NLLB 本次长句结果遗漏末段，因此更适合短句和游戏字幕。完整测试文本、输出、限制与复现脚本见仓库中的 `docs/machine-translation-benchmark.md` 和 `tools/testing/benchmark-machine-translation.mjs`。

## 词库如何运作

1. 客户端启动后下载并缓存通用词库和用户选择的游戏词库；游戏词库优先于通用词库。通用库始终启用，其中的常见片假名排除项用于阻止无意义搜索，并不强制产生译文。
2. 在“词库、缓存与学习辅助”模式下，依次检查用户手动修订、远程游戏/通用词库和本地学习结果。完整短词可直接替换；句中已知术语按较长词优先组合，并作为强制术语提示交给核心翻译模型。
3. 未解析的片假名会带当前游戏名称或用户自定义关键词，按照所选的 Wiki、Brave、百度千帆或远程搜索模型进行查询。查询在后台执行，不阻塞当前帧翻译；学习结果从下一次 OCR 开始生效。
4. 只有启用“远程视觉识别”，并且配置的搜索链均没有结果时，客户端才会发送当前文字区域截图、原始 OCR 文本和游戏信息给用户配置的多模态模型，用于纠正 OCR 与生成术语映射。
5. 本地只持久化经过长度、结构和标点过滤的专有名词、单词与短标签。不会把视频、截图、完整对白或连续剧情文本上传到 NSTrans 社区服务器。
6. “共享本地词库贡献”默认关闭。用户主动开启并填写客户端密钥后，合规的短词条才会提交社区；API 新增或修改的可信度 `+1`，网页控制台人工新增或修改 `+3`。同一原文可保留最多三条不同译文，客户端下载评分最高的候选。
7. 选择“OCR 原文直送核心翻译”会绕过翻译词库、术语搜索与学习入库，仅保留用户另行启用的远程视觉识别能力。

## 隐私和模型许可

远程 LLM、网页机翻和远程视觉识别会把完成对应请求所必需的文本或局部截图直接发送给用户选择的第三方服务，但不会经过或保存于 NSTrans 社区服务器。本机 TranslateGemma 与 NLLB 模式不会外发待翻译文本。
